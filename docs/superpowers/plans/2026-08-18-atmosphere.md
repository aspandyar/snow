# Атмосфера — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Превратить объект на плоскости в пейзаж: небо, дымка, туман по рельефу и дальние планы.

**Architecture:** Панорама HDRI подключается готовым компонентом `<Environment>` из drei и служит и фоном, и источником окружающего освещения. Дымка — встроенный экспоненциальный туман three. Туман по земле — отдельная полупрозрачная поверхность, построенная по той же функции высоты, что и земля. Гряды — плоскости, изогнутые одномерным профилем из финитных колоколов, стоящие за краем равнины и бледнеющие от дымки, а не от заданного цвета.

**Tech Stack:** three 0.185.1, @react-three/fiber 9.7.0, @react-three/drei 10.7.8, Vitest 4.1.10.

Спека: `docs/superpowers/specs/2026-08-18-atmosphere-design.md`.

## Global Constraints

- **Все числа сцены — только в `lib/config.ts`.** Исключение: настройки конвертации в `scripts/` — конфиг попадает в браузерный пакет.
- **Каждое число в конфиге сопровождается комментарием**: почему именно столько и что сломается иначе.
- **Комментарии, имена в конфиге, спеки и планы — по-русски.**
- **Сообщения коммитов и тексты PR — ПО-АНГЛИЙСКИ** (соглашение проекта, `AGENTS.md`).
- **Ни одной строки самописного шейдера.**
- **`useFrame` только с приоритетом по умолчанию.**
- **Версии пакетов, влияющих на картинку, закрепляются точно.**
- **База — `master`**, ветка `ft/atmosphere`.
- **Скриншоты снимает контроллер** на СОБРАННОЙ версии: сервер разработки в этом проекте теряет контекст WebGL, это известное ограничение. Исполнители серверы не трогают.

```ts
  /** Панорама. Формат HDR, а не WebP: нужен полный диапазон яркости,
   *  иначе панорама перестанет работать источником освещения. */
  панорама: '/textures/sky.hdr',

  /** Яркость панорамы как фона. Отдельно от освещения намеренно: фон

   *  снег уходит в белое и теряет светотень, по которой читается рельеф.
   *  Ноль — кирпичи отражают пустоту и выглядят вырезанными из кадра. */

   *  её в атмосферу. Больше 0.3 — небо становится однородной кашей. */
  размытие: 0.08,
}
```

- [ ] **Шаг 1: Дополнить конфиг**

## Задача 3: Туман, стелющийся по рельефу

**Files:** `lib/terrain/height.ts`, `lib/config.ts`, `components/scene/GroundFog.tsx`, `components/scene/SceneCanvas.tsx`, `tests/atmosphere.test.ts`

**Interfaces:** produces `высотаТумана(высотаЗемли: number, надЗемлёй: number): number`

Это третий потребитель функции высоты, ради которого её и выносили отдельным
файлом. Туман обязан повторять рельеф: плоский лист срежет холмы, и дюны
будут торчать из него, как из воды.

- [ ] **Шаг 1: Написать падающий тест**

Файл `tests/atmosphere.test.ts`:

```ts
import { describe, expect, it } from 'vitest'

import { создатьВысотуРельефа, высотаТумана, type ПараметрыРельефа } from '@/lib/terrain/height'

const параметры: ПараметрыРельефа = {
  зерно: 4242,
  наст: { амплитуда: 0.5, частота: 0.05, октав: 3 },
  дюны: [{ x: 0, z: 0, радиус: 40, высота: 5 }],
}

describe('туман по рельефу', () => {
  const земля = создатьВысотуРельефа(параметры)

  it('отстоит от земли ровно на заданную высоту в любой точке', () => {
    // Плоский лист срезал бы холмы, и дюны торчали бы из тумана,
    // как из воды. Туман обязан повторять рельеф.
    for (const [x, z] of [[0, 0], [15, -22], [-60, 40], [120, 120]]) {
      expect(высотаТумана(земля(x, z), 1.5) - земля(x, z)).toBeCloseTo(1.5, 12)
    }
  })

  it('над дюной поднимается вместе с ней', () => {
    const наДюне = высотаТумана(земля(0, 0), 1.5)
    const вдали = высотаТумана(земля(300, 300), 1.5)
    expect(наДюне).toBeGreaterThan(вдали)
  })
})
```

- [ ] **Шаг 2: Убедиться, что тест падает, затем реализовать**

```ts
/** Высота поверхности тумана над точкой земли.
 *
 *  Вынесено функцией не ради сложности — она тривиальна, — а ради теста:
 *  соблазн положить туман плоским листом на постоянной высоте велик, и
 *  на общем плане разница почти не видна. Видна она там, где туман
 *  срезает дюну, и замечается это обычно через этап. */
export function высотаТумана(высотаЗемли: number, надЗемлёй: number): number {
  return высотаЗемли + надЗемлёй
}
```

- [ ] **Шаг 3: Дополнить конфиг**

```ts
export const туман = {
  /** На сколько метров поверхность тумана поднята над землёй. Меньше
   *  метра — туман сливается со снегом и не читается вовсе. Больше
   *  четырёх — он поднимается выше дюн, и рельеф под ним пропадает. */
  надЗемлёй: 1.5,

  /** Плотность сетки поверхности тумана. Заметно грубее земли: у тумана
   *  нет ни бликов, ни резких краёв, и мелкие подробности рельефа в нём
   *  всё равно не видны, а вершин он стоит столько же. */
  сегментов: 96,

  /** Непрозрачность. Выше 0.5 туман превращается в молоко и съедает
   *  равнину целиком. Ноль — этапа не было. */
  непрозрачность: 0.28,

  /** Цвет. Тот же, что у дымки: два тумана в одном кадре разного цвета
   *  сразу читаются как ошибка. */
  цвет: '#dfe4e8',
}
```

`components/scene/GroundFog.tsx` строится по образцу `Snowfield.tsx`:

## Задача 4: Дальние гряды

**Files:** `lib/terrain/height.ts`, `lib/config.ts`, `components/scene/Ridges.tsx`, `components/scene/SceneCanvas.tsx`, `tests/atmosphere.test.ts`

**Interfaces:** produces `профильГряды(x: number, вершины: Дюна[]): number`

Гряды закрывают край равнины — сейчас он виден прямой линией на горизонте и
первым выдаёт в сцене макет.

- [ ] **Шаг 1: Написать падающий тест**

```ts
describe('профиль гряды', () => {
  const вершины = [
    { x: -40, z: 0, радиус: 60, высота: 18 },
    { x: 50, z: 0, радиус: 45, высота: 12 },
  ]

  it('за пределами всех вершин ровно ноль', () => {
    expect(профильГряды(-300, вершины)).toBe(0)
    expect(профильГряды(400, вершины)).toBe(0)
  })

  it('в вершине даёт её высоту', () => {
    expect(профильГряды(-40, вершины)).toBeCloseTo(18, 6)
  })

  it('перекрывающиеся вершины складываются', () => {
    const рядом = [
      { x: 0, z: 0, радиус: 50, высота: 10 },
      { x: 0, z: 0, радиус: 50, высота: 5 },
    ]
    expect(профильГряды(0, рядом)).toBeCloseTo(15, 6)
  })
})

describe('расстановка гряд', () => {
  it('все гряды стоят за краем равнины', () => {
    // Гряда внутри равнины воткнулась бы в снег и читалась бы не планом,
    // а торчащим из земли куском.
    for (const г of гряды.планы) {
      expect(Math.abs(г.расстояние)).toBeGreaterThan(рельеф.размер / 2)
    }
  })

  it('каждый следующий план дальше предыдущего', () => {
    const расстояния = гряды.планы.map((г) => г.расстояние)
    for (let i = 1; i < расстояния.length; i++) {
      expect(расстояния[i]).toBeGreaterThan(расстояния[i - 1])
    }
  })
})
```

- [ ] **Шаг 2: Реализовать профиль**

```ts
/** Одномерный профиль гряды: сумма финитных колоколов вдоль оси X.
 *
 *  Тот же колокол, что у дюн, и по той же причине: у гауссовой кривой
 *  бесконечный хвост, и дальняя вершина незаметно приподнимала бы всю
 *  гряду по всей длине. Здесь за радиусом ровно ноль. */
export function профильГряды(x: number, вершины: Дюна[]): number {
  let высота = 0
  for (const вершина of вершины) высота += вкладДюны(вершина, x, вершина.z)
  return высота
}
```

- [ ] **Шаг 3: Дополнить конфиг**

Раздел `гряды` со списком планов: расстояние, ширина, список вершин.
Планы перечисляются от ближнего к дальнему.

**Цвет грядам не задаётся.** Они бледнеют от дымки, и это принципиально:
крашеные вручную планы разъедутся с землёй по тону при первой же правке
тумана, и это будет видно сразу.
