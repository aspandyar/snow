# Прокрутка — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Прокрутка страницы ведёт камеру по заданной траектории; сцена зависит ровно от одного числа.

**Architecture:** Положение прокрутки превращается чистой функцией в число от нуля до единицы и кладётся в хранилище zustand. Камера читает его в кадре и идёт по кривой Катмулла-Рома через четыре точки; отдельная такая же кривая ведёт цель взгляда. Блок сцены высотой в четыре экрана, холст внутри липкий. Ниже — заглушка лендинга с отрицательным отступом, связанным с порогом нахлёста формулой.

**Tech Stack:** three 0.185.1, @react-three/fiber 9.7.0, zustand 5.0.15, Vitest 4.1.10.

Спека: `docs/superpowers/specs/2026-08-20-scroll-design.md`.

## Global Constraints

- **Все числа сцены — только в `lib/config.ts`**, каждое с комментарием «почему именно столько».
- **Комментарии по-русски. Коммиты и PR — ПО-АНГЛИЙСКИ** (`AGENTS.md`).
- **Ни одной строки самописного шейдера.**
- **`useFrame` только с приоритетом по умолчанию** — иначе R3F отключает автоматическую отрисовку и экран чернеет без ошибок.
- **Сцена зависит ровно от одного числа** — прогресса. Никаких вторых величин.
- **База — `master`**, ветка `ft/scroll`.
- **Скриншоты снимает контроллер на СОБРАННОЙ версии** (порт 3200): сервер разработки теряет контекст WebGL. Исполнители серверы не трогают.

## Задача 1: Прогресс прокрутки и порог нахлёста

**Files:** `lib/scroll/progress.ts`, `tests/scroll.test.ts`

**Interfaces:** produces
`прогрессПрокрутки(сдвиг, высотаБлока, высотаОкна): number`,
`порогНахлёста(нахлёстВЭкранах, высотаВЭкранах): number`

- [ ] **Шаг 1: Написать падающий тест**

Файл `tests/scroll.test.ts`:

```ts
import { describe, expect, it } from 'vitest'

import { порогНахлёста, прогрессПрокрутки } from '@/lib/scroll/progress'

const ОКНО = 900
const БЛОК = ОКНО * 4

describe('прогресс прокрутки', () => {
  it('ноль в начале и единица в конце', () => {
    expect(прогрессПрокрутки(0, БЛОК, ОКНО)).toBe(0)
    expect(прогрессПрокрутки(БЛОК - ОКНО, БЛОК, ОКНО)).toBe(1)
  })

  it('середина пути даёт половину', () => {
    expect(прогрессПрокрутки((БЛОК - ОКНО) / 2, БЛОК, ОКНО)).toBeCloseTo(0.5, 12)
  })

  it('зажат в границах за пределами блока', () => {
    // Прокрутка вверх до отскока и вниз за конец блока не должны
    // выбрасывать камеру за края траектории.
    expect(прогрессПрокрутки(-500, БЛОК, ОКНО)).toBe(0)
    expect(прогрессПрокрутки(БЛОК * 10, БЛОК, ОКНО)).toBe(1)
  })

  it('НЕ зависит от высоты окна', () => {
    // Главное свойство: сцена зависит ровно от одного числа, и это число
    // одинаково на любом экране. Иначе кадр поедет при смене размера
    // окна и на мобильных, где адресная строка меняет высоту на ходу.
    const малое = прогрессПрокрутки((БЛОК - ОКНО) * 0.37, БЛОК, ОКНО)
    const большое = прогрессПрокрутки((ОКНО * 8 - ОКНО * 2) * 0.37, ОКНО * 8, ОКНО * 2)
    expect(малое).toBeCloseTo(большое, 12)
  })

  it('вырожденный блок не даёт деления на ноль', () => {
    expect(прогрессПрокрутки(100, ОКНО, ОКНО)).toBe(0)
    expect(прогрессПрокрутки(100, 0, ОКНО)).toBe(0)
  })
})

describe('порог нахлёста', () => {
  it('считается по формуле 1 − нахлёст / (экранов − 1)', () => {
    // Нахлёст съедает прокрутку с КОНЦА: страница начинает закрывать
    // кадр раньше, чем траектория доиграна.
    expect(порогНахлёста(1, 4)).toBeCloseTo(1 - 1 / 3, 12)
    expect(порогНахлёста(0.5, 4)).toBeCloseTo(1 - 0.5 / 3, 12)
  })

  it('без нахлёста порог равен единице', () => {
    expect(порогНахлёста(0, 4)).toBe(1)
  })

  it('больше нахлёст — раньше порог', () => {
    // Связь, из-за которой эти два числа нельзя править по отдельности:
    // сдвинешь нахлёст, не сдвинув пороги фаз, — страница полезет
    // поверх недоигранного перехода.
    expect(порогНахлёста(1.5, 4)).toBeLessThan(порогНахлёста(0.5, 4))
  })

  it('зажат в границах при нелепых значениях', () => {
    expect(порогНахлёста(99, 4)).toBe(0)
    expect(порогНахлёста(1, 1)).toBe(0)
  })
})
```

- [ ] **Шаг 2: Убедиться, что тесты падают, затем реализовать**

`lib/scroll/progress.ts` — две чистые функции. Прогресс: пролистанная часть
делится на ту, которую вообще можно пролистать (`высотаБлока − высотаОкна`),
результат зажимается в ноль-единицу. Порог: `1 − нахлёст / (экранов − 1)`,
тоже с зажимом. Обе защищены от деления на ноль.

## Задача 2: Хранилище и разметка страницы

**Files:** `lib/scroll/store.ts`, `components/scene/ScrollDriver.tsx`, `app/page.tsx`, `lib/config.ts`

- [ ] **Шаг 1: Дополнить конфиг**

```ts
export const прокрутка = {
  /** Высота блока со сценой в экранах. Четыре — столько нужно, чтобы
   *  камера прошла траекторию без спешки: на двух зритель проскакивает
   *  её одним движением колеса, на восьми начинает скучать между
   *  точками. Изменение этого числа МЕНЯЕТ порог нахлёста — они связаны
   *  формулой, см. порогНахлёста. */
  экранов: 4,

  /** Насколько лендинг наезжает на хвост сцены, в экранах. Без нахлёста
   *  зритель, уже отсмотревший переход, ещё какое-то время пялится в
   *  кадр, залитый ровным цветом. Больше двух — страница закроет кадр
   *  раньше, чем траектория доиграна. */
  нахлёстВЭкранах: 1,
}
```

- [ ] **Шаг 2: Хранилище**

`lib/scroll/store.ts` — минимальное хранилище zustand с одним полем
`прогресс` и установщиком.

**Читать его в кадре нужно через `getState()`, а не хуком.** Хук подписал
бы компонент на изменения, и сцена перерисовывалась бы на каждый пиксель
прокрутки — это её и положит.

- [ ] **Шаг 3: Толкатель прогресса**

`components/scene/ScrollDriver.tsx`: в `useFrame` читает положение
прокрутки окна и высоту блока, считает прогресс чистой функцией из задачи 1
и кладёт в хранилище.

Именно в кадре, а не по событию прокрутки: событие приходит чаще кадра и
заставляет считать впустую, а на мобильных ещё и запаздывает за инерцией.

Компонент ставится ПЕРВЫМ в дереве сцены: обработчики кадра при одинаковом
приоритете вызываются в порядке подписки, и камера должна читать уже
посчитанное число.

- [ ] **Шаг 4: Разметка страницы**

`app/page.tsx`: блок высотой `экранов × 100dvh`, внутри липкий контейнер
высотой в экран с холстом. Ниже — заглушка лендинга: пустой блок высотой
в два экрана с отрицательным верхним отступом `нахлёстВЭкранах × 100dvh` и
фоном цвета `сцена.фон`.

Заглушка не украшение: она делает связь нахлёста и порога видимой уже
сейчас. Настоящий лендинг придёт на своём этапе и займёт её место.

Единицы — `dvh`, а не `vh`: на мобильных адресная строка появляется и
исчезает, и `vh` даёт скачок высоты на ходу.

## Задача 3: Камера по траектории

**Files:** `components/scene/CameraRig.tsx`, `components/scene/SceneCanvas.tsx`, `lib/config.ts`

- [ ] **Шаг 1: Точки траектории в конфиг**

Раздел `траектория`: четыре точки положения камеры и четыре точки цели
взгляда. Начальная точка — примерно там, где сейчас стоит обзорная камера,
чтобы первый кадр не изменился.

Каждая точка с комментарием, что зритель видит в этот момент.

**Проверить, что траектория не уходит ниже снега.** Тестом это не поймать:
высота земли зависит от шума, а «красиво» не формализуется. Проверяется
глазами, и об этом должен быть комментарий.

- [ ] **Шаг 2: Компонент камеры**

`components/scene/CameraRig.tsx`: две кривые `CatmullRomCurve3`, построенные
один раз. В `useFrame` прогресс читается из хранилища через `getState()`,
по нему берётся точка на каждой кривой, камера ставится в первую и
смотрит на вторую.

Точка берётся `getPointAt`, а не `getPoint`: первый идёт по длине дуги, и
камера движется равномерно. Второй идёт по параметру, и скорость скачет
между точками — на глаз это читается как рывки.

- [ ] **Шаг 3: Убрать OrbitControls**

Удалить из `SceneCanvas.tsx`. Ручное вращение и прокрутка спорят за колесо
мыши, а траектория перестаёт быть предсказуемой.
