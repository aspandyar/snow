## 1. Что строим целиком

Одностраничный сайт с трёхмерной сценой. Ледяная сфера, сложенная из кирпичей,
парит над заснеженной равниной. Прокрутка ведёт камеру по заданной траектории.
В конце прокрутки играет переход, и открывается обычный лендинг, который
объясняет, как эта сцена устроена.

Эта спека описывает только первые два этапа. Сцена целиком — не один
подпроект, а десяток; попытка описать всё одним документом даст документ,
который устареет на третьей ветке.

### Стек

Next.js (App Router), React, TypeScript, React Three Fiber, drei,
Tailwind CSS v4, zustand для состояния прокрутки, Vitest для тестов.

## 4. Сквозные принципы

### Все числа в одном файле

`lib/config.ts` — единственное место, где в проекте есть числовые константы.
Ни в компонентах, ни в шейдерах чисел быть не должно. Человек меняет число
в конфиге — меняется картинка. Настройка сцены сводится к правке одного файла.

Каждое число сопровождается комментарием, объясняющим не «что это»,
а **почему именно столько** и **что сломается**, если поставить иначе.

### Комментарии объясняют «почему»

Особенно там, где решение выглядит странным. У каждой странности в этом
проекте есть причина, и без неё следующий человек (или следующая нейросеть)
вернёт «как правильно» и сломает.

### Готовые компоненты вместо своих шейдеров

Максимально использовать drei и готовые эффекты постобработки. Каждый
самописный шейдер — это риск и время. В итоговом проекте самописный шейдер
ровно один: переход (этап 7).

### Язык

Текст на русском, без англицизмов там, где есть русское слово.

## 7. Этап 1 — ветка `ft/sphere`

### 7.1 Раскладка: чистая функция

`lib/layout/bricks.ts` экспортирует функцию, принимающую объект
параметров и возвращающую массив кирпичей:

```
{ позиция, кватернион, масштаб, нормаль, кольцо, номерВКольце }
```

Параметры передаются аргументом, а не читаются из конфига. Функция не
импортирует `config.ts` — иначе её нельзя протестировать независимо.

### 7.2 Математика колец

Шаг по широте:

```
Δθ = π / rings
θᵢ = (i + ½) · Δθ,   i = 0 … rings−1
```

Широта берётся **в середине** кольца, а не на границе. Это не косметика:
на границе при `i = 0` широта равна нулю, нормаль совпадает с мировой
вертикалью, и векторное произведение для касательной вырождается в ноль.
Середина кольца гарантирует, что этого не случится ни при каком `rings`.

Количество кирпичей в кольце:

```
countᵢ = round(k · rings · sin θᵢ)
```

Угол вдоль кольца:

```
φⱼ = (j + смещениеВразбежку · (i mod 2)) · 2π / countᵢ
```

Позиция центра (вертикаль — ось Y):

```
позиция = (R − толщина/2) · (sin θ cos φ,  cos θ,  sin θ sin φ)
```

Центр кладётся на `R − толщина/2`, а не на `R`. Так `radius` в конфиге
означает внешнюю поверхность кладки — то, что видно на экране, а не
воображаемую срединную поверхность.

### 7.3 Почему кирпич выходит именно такой формы

Высота кольца по дуге: `R · Δθ = πR / rings`.

Ширина кирпича: длина кольца `2πR sin θ`, делённая на `countᵢ`:

```
2πR sin θ / (k · rings · sin θ) = 2πR / (k · rings)
```

Синусы сокращаются — **ширина точно постоянна на всех кольцах**, в этом
и весь смысл формулы. Отношение ширины к высоте равно `2/k`:

- `k = 2` даёт точный квадрат — плитку, а не кладку;
- `k = 1` даёт кирпич два к одному. **Принято `k = 1`.**

При `rings = 28` и `k = 1` выходит около 500 кирпичей.

### 7.4 Разворот кирпича

Полным базисом из трёх осей:

```
n = нормализованная позиция              наружу
t = нормализовать(вертикаль × n)         вдоль кольца
b = n × t                                вдоль меридиана
```

Матрица со столбцами `[t, b, n]` переводится в кватернион. Базис
правосторонний: `t × b = n`.

Поворотом «из вектора в вектор» пользоваться **нельзя**. Он оставляет
вращение вокруг нормали незакреплённым, и кладка кренится: сфера
собирается, но кирпичи стоят пьяно. Это самая коварная из ошибок —
она проявляется не сразу.

Локальные оси геометрии: X вдоль кольца (ширина), Y вдоль меридиана
(высота), Z по нормали (толщина).

Масштаб:

```
масштаб = (ширинаДуги · (1 − шов),  высотаДуги · (1 − шов),  толщина)
```

### 7.5 Отрисовка

Один `instancedMesh`. Геометрия — `RoundedBoxGeometry` из drei, материал —
`MeshPhysicalMaterial` со `sheen`.

Фаска обязательна: на скруглении свет собирается в яркую полосу,
у острого ребра отражение обрывается и объект читается пластиковым.

Контурное свечение кирпичей — это встроенное свойство `sheen`, придуманное
для ткани. Ни одной строки шейдера.

Базовые матрицы записываются один раз при сборке. Каждый кадр переписывается
только смещение от наведения.

**Почему голый `instancedMesh`, а не `<Instances>` из drei.** `<Instance>` —
это узел React на каждый кирпич, полтысячи узлов со ссылками. Декларативно
и удобно, пока положения задаются один раз. Но отклонение от курсора требует
пересчёта матриц каждый кадр в обход React через ссылки — то есть
декларативность теряется всё равно, а полтысячи узлов остаются.

**Почему не отдельный меш на кирпич.** Пятьсот вызовов отрисовки плюс
столько же на теневую карту — порядка трёх-пяти миллисекунд процессорного
времени. Это не катастрофа: главный рычаг в этой сцене — количество
пикселей, а не полигонов. Но эти миллисекунды берутся из того же бюджета,
где уже сидят свечение и переход, а инстансинг даёт их даром.

**Почему не смещение в вершинном шейдере.** Дешевле по процессору, но это
второй самописный шейдер в проекте вопреки принципу. Экономия измеряется
долями миллисекунды и не стоит нарушенного правила.

### 7.6 Наведение курсором

Луч из камеры через курсор пересекается с **невидимой гладкой сферой**
радиуса `R` — одно аналитическое решение.

Встроенным `onPointerMove` по инстансам пользоваться нельзя: three.js
переберёт все инстансы, а `RoundedBoxGeometry` — это порядка полутора сотен
треугольников. Пятьсот кирпичей дают семьдесят пять тысяч проверок на
**каждое** движение мыши, а их до ста двадцати в секунду. Это та же ошибка,
от которой предостерегает раздел про следы на снегу.

Если пересечения нет — цель смещения обнуляется для всех кирпичей.

Иначе, для точки касания `P` и её направления `p̂ = P/|P|`, у каждого
кирпича:

```
косинус  = n̂ᵢ · p̂
влияние  = smoothstep(cos(угловойРадиус), 1, косинус)
цельᵢ    = максСмещение · влияние
```

Сравнение идёт по косинусу, а не по углу: `acos` на полтысячи кирпичей
в каждом кадре не нужен, порог переводится в косинус один раз.

Текущее смещение подтягивается к цели кадронезависимо:

```
текущееᵢ += (цельᵢ − текущееᵢ) · (1 − exp(−скорость · dt))
```

Экспонента, а не линейная доля: иначе скорость возврата зависит от частоты
кадров, и на слабой машине кирпичи возвращаются медленнее, чем на быстрой.

Смещение уходит в матрицу как сдвиг вдоль нормали:

```
позицияᵢ = базоваяПозицияᵢ + n̂ᵢ · текущееᵢ
```

Кирпичи возвращаются сами, без таймеров и списка задетых.

### 7.7 Траектории

`<Segments>` из drei. Отрезок рисуется от базовой позиции кирпича к текущей
и только если `текущееᵢ > порогТраектории` — это несколько десятков отрезков
вокруг курсора, а не полтысячи.

Толщина линии задаётся в пикселях, поэтому берётся именно `<Segments>`,
а не `lineSegments` из three.

### 7.8 Свет

В этой ветке — базовый, только чтобы форма читалась. Тонкая настройка
яркостей переносится в `ft/atmosphere`.

Состав: точечный источник внутри сферы, слабый рассеянный, самосветящийся
шарик внутри с яркостью выше единицы.

Свет выходит через зазоры между кирпичами, поэтому нижние грани оказываются
ярче верхних — снаружи так не бывает, и глаз сразу считывает, что внутри
что-то есть.

У точечного света **обязательно** ограничивается дальность. Иначе на этапе 2
он достанет до снега и выбьет землю под сферой в белое пятно.

Самосветящийся шарик ничего не освещает, но ярко виден через щели и попадает
в ореол свечения. Это главный и безопасный рычаг яркости.

### 7.9 Границы ветки

**Не входит:** земля, небо, туман, прокрутка, постобработка, лендинг.

Фон — ровная заливка цветом из конфига. Камера — `OrbitControls`, временно,
до ветки `ft/scroll`.

Цвет кирпича задаётся **темнее** будущего снега. Ошибка, которую легко
допустить: сделать снег белым, а объект светлым — тогда объект растворяется
в фоне. Светиться должны только рёбра и швы. Проверить это можно уже сейчас,
подобрав фон под цвет будущего снега.

### 7.10 Порядок шагов внутри ветки

| Шаг | Что делается | Что проверяется |
|---|---|---|
| 1 | раскладка, тесты, плоский материал, отладочные оси | оси не пляшут, швы ровные |
| 2 | фаска, `sheen`, свет | свет собирается в полосу на скруглении |
| 3 | наведение, отклонение, траектории | отклик курсора, возврат кирпичей |
| 4 | PR с описанием и снимками | |

Порядок именно такой, потому что материал с фаской и `sheen` **маскирует**
кривой разворот кирпича. Если включить красоту сразу, пьяная кладка вылезет
через две ветки, когда искать будет негде.

### 7.11 Тесты

Vitest, только чистая функция раскладки:

- в каждом кольце ровно `round(k · rings · sin θᵢ)` кирпичей;
- все центры на сфере: `|позиция| ≈ R − толщина/2`;
- кватернионы нормированы: `|q| = 1`;
- **кирпичи не перекошены**: касательная горизонтальна, `|t · вертикаль| < 10⁻⁶`
  — это и есть проверка от пьяной кладки, главный тест этапа;
- нормаль сонаправлена с направлением от центра: `n̂ · позиция̂ > 0.999`;
- соседи в кольце не пересекаются: угловой шаг ≥ угловая ширина плюс шов;
- ширина кирпича одинакова на всех кольцах с точностью до округления.

Параметры задаются **прямо в тесте**, не берутся из `config.ts`. Иначе тест
краснеет от безобидной правки числа, которое пользователь крутит руками.

## 8. Конфиг: заготовка раздела «сфера»

Показывает требуемый стиль комментариев. Значения — стартовые, подбираются
по скриншотам.

```ts
export const сфера = {
  /** Радиус внешней поверхности кладки, метры. Задаёт масштаб всему
   *  остальному: от него считаются размер кирпича, дальность точечного
   *  света и высота дюн на этапе 2. Менять — значит перенастраивать
   *  сцену целиком. */
  radius: 6,

  /** Колец по широте. Единственный рычаг плотности кладки: ширина и
   *  высота кирпича следуют за ним сами. Меньше 12 — сфера читается
   *  многогранником. Больше 40 — швы сливаются в шум, а кирпичей
   *  переваливает за тысячу. */
  rings: 28,

  /** Коэффициент в формуле count = round(k · rings · sin θ).
   *  Задаёт пропорцию кирпича: отношение ширины к высоте равно 2/k.
   *  k = 1 — кирпич два к одному, k = 2 — квадратная плитка.
   *  Плитка читается как мозаика, а не как кладка. */
  k: 1,

  /** Толщина кирпича по нормали, метры. Видна только на отклонённых
   *  кирпичах и в щелях, через которые бьёт внутренний свет. Слишком
   *  тонкий — щели не читаются, слишком толстый — сфера выглядит
   *  сложенной из брусков. */
  толщина: 0.35,

  /** Шов как доля от размера кирпича. Ноль — кирпичи смыкаются и
   *  внутренний свет наружу не выходит, весь замысел со свечением
   *  изнутри пропадает. Больше 0.15 — кладка распадается на россыпь. */
  шов: 0.06,

  /** Фаска как доля от толщины. Обязательна: на скруглении свет
   *  собирается в яркую полосу, у острого ребра отражение обрывается
   *  и объект читается пластиковым. Должна быть строго меньше
   *  половины наименьшей стороны, иначе геометрия вырождается. */
  фаска: 0.25,

  /** Смещение нечётных колец вдоль кольца, в долях шага. 0.5 даёт
   *  кладку вразбежку, 0 — стыки в одну линию по меридиану, что
   *  читается как шов на глобусе. */
  смещениеВразбежку: 0.5,
}

export const наведение = {
  /** Угловой радиус влияния курсора, радианы. Считается от точки
   *  касания по поверхности сферы. Доля затронутых кирпичей равна
   *  (1 − cos α)/2, то есть при 0.3 в движении около одиннадцати
   *  кирпичей из пятисот. Меньше 0.15 — шевелятся два-три и эффект
   *  незаметен. Больше 0.6 — за сорок, и сфера теряет форму. */
  угловойРадиус: 0.3,

  /** Максимальное смещение кирпича вдоль нормали, метры. Держать
   *  строго меньше толщины: на смещении, равном толщине, кирпич
   *  отрывается от кладки полностью и под ним видна пустота —
   *  сфера читается дырявой, а не дышащей. */
  максСмещение: 0.3,

  /** Скорость подтягивания к цели, 1/с, в показателе экспоненты.
   *  Экспонента, а не линейная доля, — иначе возврат зависит от
   *  частоты кадров. Меньше 3 — кирпичи текут как желе,
   *  больше 15 — движение читается как рывок. */
  скорость: 8,

  /** Порог, ниже которого траектория не рисуется, метры. Без него
   *  полтысячи отрезков нулевой длины попадают в <Segments>. */
  порогТраектории: 0.01,
}
```

## 9. Риски

**Полюсные кирпичи с растянутой фаской.** При инстансинге геометрия одна
на всех, разница в размерах задаётся масштабом, а неравномерный масштаб
растягивает и фаску. Синусы в формуле сокращаются, поэтому ширина точно
постоянна — портит её только округление. У экватора при `rings = 28`
ошибка округления составляет доли процента, у полюса `count` падает до
двух-трёх и разброс достигает 20–25%. Затронуто три-шесть кирпичей у
каждого полюса из полутысячи. Смотрим на скриншоте шага 2; если видно —
полюсные кольца выносятся во второй инстансированный меш со своей
геометрией.

**Доступность `roundedBoxGeometry` как элемента JSX.** Зависит от версии
drei. Проверяется на шаге 2. Запасной вариант — собрать геометрию вручную
и передать объектом.

**Цена `sheen` в кадре.** `MeshPhysicalMaterial` со `sheen` дороже обычного.
Замеряется на этапе 9, не сейчас.

**Node 25 — нечётная версия, не LTS.** Next.js и `sharp` (понадобится на
этапе 3 для конвертации текстур в WebP) тестируются на 20 и 22. Сегодня не
блокер. Если на этапе 3 всплывёт странная ошибка сборки — причина, скорее
всего, здесь.

## 10. Решения, отложенные до своих этапов

**Ассеты в репозитории (этап 3).** Текстуры и панорама неба скачиваются
скриптом и по умолчанию попадают в исключения репозитория. На хостинге их
из-за этого не окажется, и сцена упадёт с ошибкой 404. Решить до этапа 3:
либо класть ассеты в репозиторий, либо запускать скачивание при сборке.

**Порог фаз прокрутки и нахлёст лендинга (этапы 6 и 8).** Нахлёст съедает
прокрутку с конца: страница начинает закрывать кадр на отметке
`1 − нахлёст / (высота секции в экранах − 1)`. Сдвинуть нахлёст, не сдвинув
пороги фаз, — страница полезет поверх недоигранного перехода.

**Состав цепочки постобработки (этап 7).** Менять на ходу нельзя: библиотека
пересобирает цепочку и падает на попытке сериализовать объекты сцены.
Отключать эффект режимом пропуска тоже нельзя — обратно шейдер уже не
собирается. Цепочка задаётся один раз и живёт всю прокрутку.
